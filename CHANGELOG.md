# Changelog

## 0.2.0 (unreleased)

- Locked transitive dependencies refreshed to clear known vulnerabilities: anyio 4.15.1, certifi 2026.10.23, cryptography 50.0.2, pyjwt 2.15.1 and pypdf 6.21.4 (the linter's PDF path). `pip-audit` 2.10.1 reported 56 known vulnerabilities in those five packages on the previous lock and none on this one.
- `micar_register_changes` now states `snapshot_date`, `data_age_days`, `stale` and `observatory_snapshot`, like search and summary.
- CLI `search --offset` pages through matches.
- Typed output: every tool declares a field-level `outputSchema` and a `title`; register answers add `warnings` (cached-fallback notes).
- One error model: failures return `isError: true` with a JSON text block holding `code` (`data_unavailable`, `extra_missing`, `invalid_input`, `upstream_failed`, `timeout`), `error`, `hint` and `notice`, and no `structuredContent` (which must match the success `outputSchema`; TypeScript clients check it even on errors). Any unexpected exception inside a tool becomes `upstream_failed`. Cached-fallback `warnings` name only the data files an answer read. Resource read errors carry the code and the register `notice` in their message. A missing extra or invalid JSON is now an error result, not an ordinary one; linter timeouts are caught. The CLI prints the error and exits 1, and rejects an unknown `--register`.
- Contract evals: 25 golden tasks in `tests/evals/tasks/` run through an MCP client on fictional fixtures (dates, notice, error codes, unchanged sibling output, no compliance-style keys), plus a test that versions and the registry name agree.
- Errors from register tools always carry `snapshot_date`, `data_age_days` and `stale` (as `null`).
- Resources `eu-reg://about`, `micar://summary`, `micar://changes` and the template `micar://entry/{entry_id}`; prompts `check_register_status` and `review_register_changes` that ask for the snapshot date and keep the review framing.
- Single-source `__version__`: the HTTP `User-Agent` and the MCP `serverInfo.version` (which reported the SDK's version) now state this package's version.
- The `lint` extra requires micar-whitepaper-linter 0.2.1 or newer (was 0.2.0); the lockfile uses 1.2.1, and eu-ai-act-classifier 0.2.2 as in 0.1.2. A weekly CI job also runs the contract evals with both extras upgraded to their newest releases, which users install even when the lockfile lags.
- Ranked search: each result carries `match` (`score` and `basis`, string matching only); `next_offset` pages; with no match, `similar_names` lists up to five similarly spelt names, each labelled "not a match". On a 22-query synthetic benchmark, real-match hit@1 rose from 0.18 to 0.36 (hit@5 unchanged at 0.36, since ranking only reorders literal matches); on the 14 queries with no match, `similar_names` put the intended entry first every time, as a suggestion, not a match.
- `micar_register_changes` filters by `since`, `until`, `register_slug`, `member_state`, `entity`, `entry_id` and exact `lei` (change records carry an LEI from the 2026-10-19 snapshot on), accepts the provisional change type `missing` (explained in the answer's `notice`: not a removal), and pages with `offset`/`next_offset`; the CLI mirrors them, and `changes --limit` now defaults to 50 like the tool.
- `classify_eu_ai_act_system` reports an invalid profile or a `profile_json` that is not a JSON object as an `invalid_input` error result (`isError: true`, with `code`, `hint` and `notice`) instead of 0.1.2's ordinary `{"available": true, "error": ...}` result. Only a pydantic validation error counts as an invalid profile; any other exception from the classifier is `upstream_failed`.
- Minimum mcp is now 1.30.0 (was 1.9 in 0.1.2; still below 2). Typed output and tool titles need 1.22 or newer, and 1.30.0 is the first 1.x release past every mcp advisory OSV listed for 1.22.0 on 2026-10-31: GHSA-9h52-p55h-vw2f (DNS rebinding protection off by default; fixed in 1.23.0), GHSA-jpw9-pfvf-9f58 (HTTP transports served session requests without verifying the authenticated user; 1.27.2), GHSA-vj7q-gjh5-988w (WebSocket transport without Host/Origin validation; 1.28.1), and GHSA-84m7-p3x7-pcfv (unbounded StreamableHTTP session accumulation), GHSA-5h93-6whr-6q8j, GHSA-rwrf-2pqf-9j8j and GHSA-w4fh-qvv9-3v23 (all 1.30.0). Several concern the HTTP transport this server offers with `--transport streamable-http`.
- After a failed refresh, the register tools serve the last good copy for five minutes (`FALLBACK_RETRY_SECONDS`) without contacting GitHub, instead of repeating the three fetch attempts on every call; `warnings` still name the files served this way, and a successful refresh ends the window.
- `classify_eu_ai_act_system` with an empty `profile_json` keeps the review notice: `notice` gives the schema sentence, then the review text ending "Not legal advice." (0.1.2 gave only the schema sentence).
- The README, which is also the PyPI description, is cut to under 350 words with absolute links only (a test checks both); the detail moves to the new `docs/overview.md` (who it's for, example output, why not just ask an LLM), `docs/clients.md` (Claude Desktop) and `docs/tools.md` (starting a pip install by full path).
- The synthetic-data test also covers the search ranking benchmark's snapshot (`tests/evals/ranking_snapshot.json`): its LEIs must contain EXAMPLE and fail the check digits, and its URLs must use reserved hosts.

## 0.1.2 (2026-10-23)

- Register answers are verifiable: each search result carries its `entry_id` and the ESMA source file (`esma_source_url`), and each register in the summary carries its `esma_source_url`; search and summary responses state `snapshot_date`, `data_age_days`, `stale` and the observatory data file the server reads (`observatory_snapshot`, on `main`; use `snapshot_date` to find the matching revision), and change responses name the observatory change log file the server reads (`changelog_source`, on `main`).
- Change records carry `still_listed` (is the entry in the latest snapshot), so `micar_register_changes` now loads the snapshot as well as the change log.
- Name search is accent-insensitive as well as case-insensitive and treats runs of whitespace as one space ("societe" finds "Société").
- CLI subcommands `search`, `summary`, `changes` print JSON without an MCP client.
- `--transport streamable-http` (with `--host`, `--port`) serves MCP over HTTP at `/mcp`, without authentication. With recent mcp releases (such as 1.28 and 1.30), only requests whose Host header is `localhost`, `127.0.0.1` or `[::1]` with a port (such as `localhost:8000`) are answered, whatever address `--host` binds to; others get HTTP 421.
- Weekly live-data check and an unlocked PyPI install smoke test in CI.
- Tools declare read-only annotations and enum parameters (`register_slug`, `change_type`); search pages with `offset`, 25 results at a time. The MCP tools now reject an unknown `register_slug` or `change_type` as an invalid argument; in 0.1.1 they returned an empty result. Minimum mcp is now 1.9 (still below 2).
- Docs, and the install hint the lint and classify tools return when their extra is missing, pin `--python 3.13` wherever the `lint`/`classify` extras are installed with uvx.
- Test fixtures and the README example, which is also the PyPI project description, use invented entities only. A fixture row copied from the live register, which the 0.1.1 README showed as synthetic search output, and the removal event invented for it in the fixture change log, are gone. A new test checks that fixture LEIs fail the check digits, fixture URLs use reserved hosts and the change log agrees with the snapshot.
- The `classify` extra requires eu-ai-act-classifier 0.2.2 or newer (was 0.2.0). Its application timeline already had the 2 December 2027 and 2 August 2028 high-risk dates and now has six more entries, dated 2 August 2025, 27 July 2026, 2 December 2026 (two), 2 August 2027 and 2 August 2030. The two dated 2 December 2026 cover Art. 5(1)(ba) and (bb) and Art. 5(1a) and (1b), and Art. 50(2) for generative systems placed on the market before 2 August 2026 (Art. 111(4)). The classifier labels the 27 July 2026, 2 December 2026 and 2 August 2030 entries as Regulation (EU) 2026/1744 entries. As the classifier's 0.2.2 changelog describes, `classify_eu_ai_act_system` output changes too: `placing_on_market_date` and `putting_into_service_date` must be ISO dates (YYYY-MM-DD), so a profile with "March 2026" is rejected; some high-risk, Art. 49(3) deployer and general-purpose AI model profiles return `requires_review` instead of `determined`; the `obligation_graph` items for Arts. 40 to 44, 47 and 48, Art. 49 where it applies, and Arts. 72 and 73 are dated 2 August 2026 instead of 2 December 2027 or 2 August 2028, `review_required` and flagged "Literal reading, confirm with counsel"; and Art. 49(1) registration is no longer listed for a system that is high-risk only as an Annex I product, or for an Annex III point 2 system, which gets a `review_required` Art. 49(5) item (registration at national level) instead. That changelog compares 0.2.2 with 0.2.1; where checked, 0.2.0 behaves like 0.2.1. Profiles may use the new fields `deployer_public_authority`, `gpai_model_placing_on_market_date` and `annex_i_section` and the prohibited-practice codes `5.1.ba` and `5.1.bb`; the schema returned for an empty `profile_json` lists the codes and adds `annex_i_sections`.
- `classify_eu_ai_act_system` returns `{"available": true, "error": ...}` instead of failing the tool call when the classifier rejects the profile (such as a non-ISO date or an unknown field) or `profile_json` is not a JSON object.
- CONTRIBUTING.md, SECURITY.md and GitHub issue forms for bugs and register data; the README drops its screenshot placeholder.
